# 直播弹幕助手 · 设计文档

日期：2026-09-03
状态：已与用户逐节确认

## 1. 目标与范围

一个 Electron 桌面应用：挂载各直播平台的网页端直播间，捕获弹幕并拆分为「用户 + 内容」，调用智谱 GLM 生成回复，并支持自动发送回直播间。

- **平台节奏**：第一期 B 站（全链路跑通）；第二期抖音；第三期快手。
- **本期范围**：B 站全链路 + 多平台适配器框架 + 卡通磨砂 UI + AI 回复引擎 + 防风控发送调度 + SQLite 历史存储 + 设置持久化。
- **非目标（本期不做）**：抖音/快手协议解析实现、移动端 App 抓取、多账号管理、弹幕统计分析报表。

## 2. 已确认的关键决策

| 决策点 | 结论 |
|---|---|
| 运行形态 | Electron 桌面应用（内嵌 WebView 加载直播间页面） |
| 弹幕捕获 | WebSocket 帧注入为主 + DOM 监听（MutationObserver）降级兜底 |
| AI 服务 | 智谱 GLM（OpenAI 兼容接口） |
| 回复去向 | 自动发送到直播间（带防风控调度；提供人工确认开关） |
| 技术栈 | Electron + Vue 3 + TypeScript + electron-vite + Pinia + better-sqlite3 |
| UI 风格 | 卡通风格（粗描边漫画感）+ 磨砂玻璃 + 小圆角直边（全局 6px） |

## 3. 总体架构与数据流

```
┌─────────────────────────── Electron 应用 ───────────────────────────┐
│  ┌─────────────┐   IPC(帧/事件)   ┌──────────────────────────────┐  │
│  │ 隐藏 WebView │ ───────────────→ │  主进程 (Node.js)             │  │
│  │ (直播间页面)  │ ←─────────────── │  平台适配器层(B站/抖音/快手)   │  │
│  │ ·注入 Hook.js│   IPC(发送指令)  │  统一弹幕总线 (EventBus)       │  │
│  │ ·WS 帧拦截   │                  │  AI 回复引擎(智谱GLM)          │  │
│  │ ·DOM 兜底    │                  │  发送调度器(防风控队列)         │  │
│  └─────────────┘                  │  SQLite 历史存储               │  │
│  ┌─────────────┐  推送事件         └──────────────────────────────┘  │
│  │ 渲染进程 UI   │ ←──────────────                                   │
│  │ (Vue3 界面)  │                                                    │
└──────────────────────────────────────────────────────────────────────┘
```

核心流程：

1. 用户在助手中输入直播间地址/房间号 → 主进程为该房间创建隐藏 WebView 加载直播间页面。
2. 注入 Hook 脚本：包装 `window.WebSocket` 拦截弹幕 WS 帧（主世界注入）；失败时自动降级为 DOM 监听模式。
3. 主进程平台适配器将原始帧解析为统一弹幕结构 → 推送 UI 展示 + 写入 SQLite。
4. 符合触发规则的弹幕 → AI 回复引擎调用智谱 GLM（强制 JSON 输出规范）。
5. 回复进入发送调度器（敏感词过滤/去重/节流/可选人工确认）→ 注入脚本在页面内模拟输入与点击发送。

关键设计约束：

- **平台适配器统一接口**：`connect(room) / disconnect() / parse(frame) / send(text)`；新增平台只新增适配器目录。
- **每平台房间一个 WebView**：支持同时挂多个直播间。
- **数据流单向**：WebView → 主进程 → UI；UI 不直接访问 WebView。

## 4. 统一弹幕数据结构

```typescript
interface DanmakuMessage {
  id: string                    // 平台消息ID（去重用）
  platform: 'bilibili' | 'douyin' | 'kuaishou'
  roomId: string
  type: 'chat' | 'enter' | 'gift' | 'like' | 'follow' | 'share'
  user: {
    uid: string
    nickname: string            // 拆分结果①：用户
    avatar?: string
    guardLevel?: number         // 舰长/粉丝团等级
  }
  content: string               // 拆分结果②：内容（chat 必填）
  gift?: { name: string; count: number; price: number }
  ts: number                    // 毫秒时间戳
  source: 'ws' | 'dom'          // 采集来源（ws=Hook模式，dom=兜底模式）
  raw?: unknown                 // 原始帧（调试用，可选存储）
}

// 房间统计事件（独立于弹幕消息，驱动顶栏人气/速率展示）
interface RoomStatEvent {
  platform: 'bilibili' | 'douyin' | 'kuaishou'
  roomId: string
  onlineCount?: number          // 在线/观看人数（平台不提供时缺省）
  danmakuRate: number           // 近 60s 弹幕条数（本地统计）
  ts: number
}
```

**兜底模式（source=dom）字段限制**：仅能可靠提取 `nickname + content`，`uid/avatar/guardLevel` 等字段允许为空字符串/缺省；`id` 用 `${roomId}:${ts}:${hash(content)}` 合成。AI 回复与发送逻辑对两模式无感知差异。

## 5. AI 接入配置与回复输出规范（智谱 GLM 强制 JSON）

### 5.1 模型接入配置

| 配置项 | 值 | 存储位置 |
|---|---|---|
| BaseURL | `https://open.bigmodel.cn/api/paas/v4` | 设置界面（默认值内置） |
| 模型名 | `glm-4.5-air` | 设置界面（默认值内置） |
| API Key | 用户私有凭据 | 仅本地：`.env.local`（gitignore）或设置界面录入 electron-store（用户数据目录，不入仓库） |

接口协议为 OpenAI 兼容（`POST {BaseURL}/chat/completions`），要求模型强制 JSON 输出（`response_format`）。Key 严禁写入任何 git 追踪的文件。

### 5.2 回复输出规范

```json
{
  "action": "reply | ignore",
  "reply_to": "用户昵称",
  "text": "回复文本",
  "emotion": "answer | thanks | greet | tease | comfort",
  "priority": "high | normal | low",
  "reason": "一句话决策理由（仅日志用）"
}
```

规范约束：

- `action=ignore`：AI 自主跳过无意义弹幕（纯 emoji 刷屏等），避免逐条强行回复。
- `text` ≤ 40 字；发送前必须经过敏感词过滤。
- `emotion` 驱动 UI 回复气泡的卡通表情与配色。
- `priority` 决定发送队列插队顺序：礼物感谢 > 提问 > 闲聊。
- 请求上下文 = 人设 Prompt（用户可编辑）+ 最近 20 条弹幕 + 该用户最近互动历史 + 该用户已回复记录（防重复）。
- 模型输出必须通过 JSON Schema 校验；校验失败重试 1 次，仍失败则丢弃并记录日志。

## 6. 发送调度器（防风控）

```
AI 回复 → 敏感词过滤 → 去重（同内容 10 分钟内不重发）
       → 队列排序（priority + 时间）
       → 随机延迟 8~25 秒发送一条
       → 频率上限：每分钟最多 2 条，每小时上限可配置
       → [可选开关] 发送前人工确认（默认关闭）
       → 连续失败 3 次自动熔断 5 分钟
```

## 7. 触发规则（可配置）

| 模式 | 说明 |
|---|---|
| 智能模式（默认） | AI 自主判断哪些弹幕值得回复 |
| 关键词模式 | 只回复命中关键词列表的弹幕 |
| 提问模式 | 只回复含 `？/?/吗/呢` 的问句 |
| 全部回复 | 每条 chat 都回复（不推荐，易风控） |

## 8. UI 设计：「漫画分格磨砂」卡通风格

- **磨砂窗口**：`backdrop-filter: blur(24px) saturate(1.6)` + 半透明底 `rgba(255,255,255,.55)`，背景为糖果渐变（粉紫 → 天蓝）。
- **小圆角直边**：全局 `border-radius: 6px`（窗口 10px）；2px 深色描边 `#2b2b3a`（漫画勾线）+ 硬阴影 `4px 4px 0`（无模糊，贴纸感）。
- **卡通元素**：圆体字体（中文系统圆体 / 英文 Nunito）；AI 回复气泡带 emotion 表情；弹幕气泡按类型着色（提问=薄荷绿、礼物=金黄、进场=淡紫、普通=磨砂白）。

布局：

```
┌─────────────────────────────────────────────────┐
│ Logo  [房间Tab]...  ⚡弹幕速率  👥人气  ⚙        │ 顶栏（磨砂）
├─────────┬──────────────────────────┬────────────┤
│ 房间管理 │   弹幕流（瀑布滚动）       │ AI 回复面板 │
│ + 添加   │ [头像][昵称][粉丝牌]+气泡  │ 待发送队列  │
│ 平台状态 │                          │ [✓发送][✗弃]│
├─────────┴──────────────────────────┴────────────┤
│ 状态栏：连接状态 | AI开关 | 模式 | 队列数          │
└─────────────────────────────────────────────────┘
```

设置抽屉：智谱 API Key、人设 Prompt、触发模式、发送频率上限、敏感词库。

## 10. 错误处理

- WS Hook 注入失败 → 自动降级 DOM 监听模式（UI 显示"兜底模式"标识）。
- 平台页面改版导致解析失败 → 记录原始帧样本日志（可脱敏开关），UI 提示适配器异常。
- GLM API 超时/限流 → 指数退避重试 2 次；失败任务进入死信队列可在 UI 重试。
- WebView 崩溃 → 自动重建 WebView 并重新注入；连续崩溃 3 次标记房间异常等待人工处理。
- 发送失败（页面结构变化）→ 截图/日志留证并熔断，避免盲发。

## 11. 测试策略

- **适配器单测**：录制真实 WS 帧样本文件 → 回放解析 → 断言统一结构字段。
- **调度器单测**：fake timers 验证随机延迟、频率上限、去重、熔断逻辑。
- **AI 规范单测**：mock GLM 响应 → JSON Schema 校验 + 超长/非法输出处理。
- **UI 组件测试**：核心组件（弹幕流、回复队列、设置抽屉）渲染快照与交互。
- **手动冒烟**：真实 B 站直播间验证捕获、回复、发送全链路。

## 13. 风险与对策

- **平台风控**：自动发送是最大风险。对策：频率硬上限 + 随机延迟 + 人工确认开关 + 敏感词过滤 + 熔断。用户需知悉仍存在账号风险。
- **页面改版**：注入选择器/协议可能失效。对策：适配器版本化 + 原始帧样本日志 + DOM 兜底。
- **弹幕高峰性能**：热门房间弹幕量大。对策：主进程解析 + UI 虚拟滚动（只保留最近 N 条渲染），SQLite 批量写入。
